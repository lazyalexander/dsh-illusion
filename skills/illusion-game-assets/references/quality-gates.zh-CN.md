# 游戏资产质量门槛

每项门槛记录为 `pass`、`needs-revision` 或 `not-observable`。

## 通用门槛

- 需求：分类、原型、用途、风格、目标引擎和单位明确。
- 尺度：写明现实或玩法尺度，比例在视觉上自洽。
- 轮廓：不依赖颜色或小细节仍能识别资产。
- 结构：父子层级、活动边界和模块边界语义稳定。
- 接地：脚、轮、根、基础、支撑、入口等与预定地面一致。
- 材质：材质差异服务于形态和功能；它们是预览属性，不等同于纹理资产。
- 修订：反馈通过稳定 ID 修改，不静默推翻已接受内容。
- 历史：每个语义节点都是独立检查点，并保留审阅、分支和导出控件。
- 导出：用户明确要求时，从已接受检查点生成 GLB 和构建 JSON。

## 游戏生产门槛

协议现在可以记录并校验所声明的枢轴、边界、挂点、碰撞归属、模块网格、材质槽成员和 LOD 成员。这只证明检查点的结构一致性，不证明目标引擎行为。

以下能力仍需外部证据；没有引擎或 DCC 回执时标记为 `not-observable`：

- 目标引擎中的枢轴与原点验收；
- 玩法碰撞行为；
- 模块吸附和接缝验收；
- UV、纹素密度和纹理贴图；
- 三角面预算、拓扑流、法线和光照 UV；
- LOD 切换和引擎侧导入；
- 蒙皮权重、变形、动画、物理和运行时行为。

不要把视觉上可信的预览描述成生产就绪资产。
