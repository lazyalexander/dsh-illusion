# 游戏建模引擎路线图

[English](GAME_MODELING_ENGINE_ROADMAP.md) | 简体中文

Illusion 目前是可审阅的模块化构建引擎，还不是完整的游戏资产生产引擎。路线图以可验收产物和引擎证据推进，不以视觉野心代替完成度。

## 阶段 1 — 资产分类与可重复基准

状态：本次版本已实现。

- 新增 `game-asset` 档案，覆盖人形、生物、建筑、载具、道具、植被、地形和环境。
- 记录原型、用途、风格、目标引擎和单位。
- 新增轮廓、结构、细节、碰撞和 LOD 阶段。
- 提供可复用 Skill、角色/交接 Agentment 契约和跨分类基准目录。

验收：全部档案变体可解析；基准覆盖所有分类；DeepSeek 可为每类发布可见 smoke 资产；历史、审阅、分支和导出控件持续可用。

### 治理基础——已实现

- 保持一个可安装协调器，同时把建模、验证和导出分成受治理的能力插件。
- 在运行前拒绝缺失依赖、依赖环、冲突、重复能力提供者和重复修改所有者。
- 把 Agentment 角色绑定到插件 ID，但不声称已经存在独立运行的 Agent 或 npm 包。

验收：内置图能确定性解析；只有 DeepSeek Modeler 拥有模型修改权；导出只拥有可下载产物；治理失败案例通过自动测试。

## 阶段 2 — 游戏语义

状态：协议与确定性引用校验已实现；目标引擎导入探针仍待完成。

- 新增明确的资产边界、枢轴/原点、插槽、材质槽、模块网格、碰撞体和 LOD 组。**已实现。**
- 在卡片中展示语义数量，并把完整声明写入构建 JSON 与 GLB 元数据。**已实现。**
- 原子校验层级引用、碰撞归属、唯一材质槽成员、递减 LOD 阈值和 LOD 成员。**已实现。** 尺度/接地和模块接缝的几何检查仍待完成。

验收：夹具可往返全部字段；非法引用原子失败；Godot、Unity、Unreal 导入探针能恢复相同的 ID、变换、槽位和分组。

## 阶段 3 — 网格与材质生产

- 增加受控网格编辑、法线、UV 集、材质槽分配、纹理引用和三角面预算。
- 分离可编辑源网格与派生运行时网格。
- 对可观察部分加入确定性的拓扑和 UV 校验。

验收：代表性道具、建筑模块、生物和载具在外部 DCC 检查中满足声明的三角面、UV、法线和材质槽门槛。

## 阶段 4 — 变形与动画

- 新增蒙皮权重、绑定姿势、约束、IK 元数据、表情、动画片段和动作测试。
- 把静止骨架证据与变形、运行时动画证据分开。

验收：人形和四足夹具通过动作套件，没有不可接受的穿插或关节塌陷；导出/导入保留骨架与动画片段。

## 阶段 5 — 引擎适配器

- 提供版本化的 Godot、Unity、Unreal 适配器、导入预设和回执。
- 在各目标引擎内验证碰撞、材质、LOD、插槽、动画、尺度和运行时实例化。

验收：空白项目可通过可重复命令或明确编辑器动作导入并实例化全部基准资产；运行时观察结果与导出成功分别记录。

## 阶段 6 — 资产库与世界组合

- 新增不可变资产版本、依赖图、套件组合、变体、场景放置和更新协调。
- 让已接受检查点和引擎导入回执可追溯到源构建。

验收：使用版本化基准资产组装一个小型可玩场景；资产修订后，系统能报告哪些实例已更新、保持锁定或需要人工处理。
